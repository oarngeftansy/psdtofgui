# Memory — 偏好与约定

- 用户要求交付前必须自检，不能只声明“应该能运行”。
- “村庄升阶”只是一份回归样例；产品必须是可扩展的通用 Figma → FairyGUI 工具，禁止针对该页面硬编码。
- 主流程是 `Figma → UIR → FGUI Plan → 新建 FairyGUI 工程/XML → 校验 → ZIP`。
- 新建工程模式不得要求用户先提供或扫描已有 FairyGUI 工程。
- 扫描已有 FairyGUI 工程仅属于“更新已有工程、复用公共资源或绑定既有组件”的可选模式。
- 转换不能静默丢失视觉或行为；无法可靠表达的能力必须明确降级或 fail closed，并给出可操作诊断。
- 通用组件映射文件保存逻辑名称和语义，不保存某个工程的真实 package/component ID。
- 所有“已修复/可交付”声明前，必须在沙箱内覆盖相关逻辑的正例、反例和全量门；自检不得控制用户电脑或 Figma。
- 能由 FairyGUI 原生表达的 Figma 内容和样式必须保留为可编辑层；只有真正不可表达的最小局部才进入“建议审核”并允许转图片，禁止为了保真把整页或整个组件泛化栅格化。
- 审核对比必须使用真实证据，并按稳定的 source node/resource identity 关联；没有真实预览时要明确说明，不能展示重复占位图冒充对比结果。
- 审核话术必须针对具体问题说明“检测结果、建议处理、可编辑性影响”；自动转换项按结构、文字、图形、组件汇总，避免每项重复同一句话。
- 插件主要面对竖屏设计稿，审核内容是核心，不得被固定底栏遮挡、压扁或塞入难以浏览的多层滚动区。
- 真实验收续接时只走产品公开、鉴权接口：不得绕过候选产物 ACL，也不得代替用户批准审核；候选获批后再下载 ZIP 并继续 FairyGUI 结构与可编辑性验收。
- PSD 替换模式以旧 FairyGUI 根组件尺寸作为 PSD 有效设计区域尺寸；PSD 文档外围安全区不属于替换内容，优先用同尺寸 PSD 图层定位有效区域，缺少证据时才允许居中推断。
- PSD → FairyGUI 替换只能改视觉皮肤；旧组件 ID、类型、Controller、Gear、Transition、Relation、组件引用和输入行为必须保留，纯视觉叠层必须 `touchable=false`。
- PSD 局部复合皮肤只允许覆盖小而明确的静态区域；大面积、纵向过高、跨功能区或密集文字条不得整体烘焙。文字继续可编辑并置于皮肤之上，Controller、按钮状态和 Transition 必须用逐状态 Editor 渲染证据验证。
