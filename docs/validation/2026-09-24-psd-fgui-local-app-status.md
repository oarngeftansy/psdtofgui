# PSD → 旧 FGUI 视觉替换：当前成果说明

更新日期：2026-09-24

## 结论

当前已经有一套可运行的 Windows 本地应用主体。它由浏览器界面和本机 Python 处理服务组成，数据与生成物保留在本机，不依赖 Figma 插件。

当前形态是开发可用版，还不是安装包或单个 `.exe`。主流程已经能用真实 PSD 和旧 FGUI 工程跑通并生成候选工程；多状态视觉映射规则尚未确定，因此还不能把所有项目都自动判定为可交付。

## 正确入口

双击仓库根目录的 `启动PSD替换工具.cmd`。

启动器会：

1. 检查并准备 Python、Node.js 和项目依赖。
2. 构建 React 操作界面。
3. 在本机可用端口启动服务，默认从 `http://localhost:8765` 开始查找。
4. 自动打开真实应用页面。

`apps/web-console/prototypes/hifi-replacement-flow-prototype.html` 只是早期交互原型，不是当前真实应用。

## 已实现的工作流

1. 导入旧 FGUI 工程 ZIP。
2. 导入 PSD，解析可见图层、复合结果、尺寸、边界和视觉能力。
3. 检查项目固定字体；外部 PNG 切图和参考效果图均为可选输入。
4. 浏览 FGUI 包目录并选择指定目录与根组件。
5. 盘点旧组件结构、引用闭包、Controller、页面、Gear、Transition、关系、实例参数和受影响对象。
6. 建立 PSD 与 FGUI 的映射工作区。
7. 保留旧组件 XML 和程序结构，在候选副本中写入 HIFI 视觉资源。
8. 生成候选工程、文件差异、对象差异和审核证据。
9. 调用本机 FairyGUI Editor 时，可执行打开、渲染、截图和像素对比检查。
10. 审核通过后下载完整候选工程 ZIP；原工程不会被直接覆盖。

## 真实样本已验证结果

测试输入为现有待替换 FGUI 工程和 `D:\SampleDesign` 中的 PSD。

- 完整保留 PSD 的可见区域，包括超出 1080 × 1920 首屏的内容。
- 隐藏图层不进入最终视觉。
- PSD 总画面为 1080 × 2340；旧根组件仍保持 1080 × 1920。
- 生成两张内部视觉资源：1080 × 2048 和 1080 × 292。
- 两张资源拼回后的结果与 PSD 复合图逐像素一致。
- FairyGUI Editor 首屏渲染像素差为 `0.0`。
- 旧对象结构保护检查和资源闭包检查通过。
- 已产出可复查的候选工程 ZIP、完整候选 PNG 和 FairyGUI Editor 工程目录。

## 当前边界

### 已能保证

- 默认静态视觉可以按 PSD 精确进入旧 FGUI 工程。
- 旧组件、Controller、Gear、Transition、实例引用和程序绑定不会被删除。
- PSD 画布外延内容不会因首屏尺寸而被裁掉。
- 候选修改发生在副本中，可审核、可重复生成。

### 尚未闭合

- PSD 通常只表达一个视觉状态，无法单独说明旧 FGUI 中多个 Controller 页面、按钮状态或 Transition 中间帧应该替换成什么。
- 当前默认 PSD 视觉层可能遮住 16 个会随状态变化的旧对象。程序逻辑仍在，但这些状态的视觉不一定能显示出来。
- “状态、参数、实例应如何参与映射”的规则等待需求方确认，因此人工修改映射工作台暂缓实现。
- 超出首屏的内容已保留，但是否能滚动仍依赖旧工程原有的 ScrollPane 或程序滚动容器；工具不会凭空改变交互结构。
- 还没有制作安装器、桌面壳、自动更新和正式发布包。

## 其他电脑试用

已提供 Windows 联网便携测试包。接收方解压后安装随包字体，再进入“应用”目录双击
`启动PSD替换工具.cmd`。首次运行会自动安装 Python 3.11 和处理依赖，不要求安装
Node.js，也不要求导入 Figma 插件。

便携包已在空运行目录中完成真实首次启动验证，应用主页返回 HTTP 200。最终 FairyGUI
渲染与像素验证仍要求接收电脑单独安装 FairyGUI Editor。
