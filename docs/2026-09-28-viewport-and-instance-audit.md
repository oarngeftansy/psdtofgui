## 已修复的错误

- Editor 6.1.4 工程里的 `pkg`、`aspect`、`autoSize`、`controller`、布局与描边等标准 XML 字段以前被当成未知字段。逐项列入可识别且原样保留的字段后，真实工程解析覆盖率为 `true`，无未知标签、未知字段或悬空组件引用。未知自定义字段仍会阻断。
- 有 3 个实际宽高为零的可见 PSD 图层此前抢占旧对象映射。现在零面积图层不能提供原位视觉资源或建立假配对；对应缺口明确留在未决记录中。
- PSD 为 1080×2340，旧组件为 1080×1920。真实 PSD 有 1080×1920 视口标记，起点为 `(0,210)`。映射评分现在按此视口比较几何，原 PSD 预览坐标不动；原位写入的局部坐标也扣除视口偏移。真实重跑从修复零面积后的 251 条未决降至 247 条，仍远高于 5。

## 共享按钮的真实 Editor 隔离验证

Delegate 和 Reward 的两份 PSD 背景各自由三片视觉叶图层组成，另各有一个独立文字层。两份 385×86 PNG 有 28 个像素不同，最大通道差 3，不能未经说明地强制共用同一资源。

隔离工程为 Reward 复制既有按钮组件定义，仅把主页旧 Reward 实例的 `src` 指向该变体，两个既有按钮的 `id`、`name`、顺序和各自 4 个子对象 ID 不变，不加覆盖层。FairyGUI Editor 6.1.4 的 F5 完整主页截图显示两份不同 PSD 底图均已加载，证据为 `.local-hifi-run/verification-20260928/variant-two-bodies-editor.png` 和 `variant-two-bodies-report.json`。变体资源 ID 的游戏侧依赖尚未验证；此隔离工程不进入正式候选。

## 仍阻断一次性交付的事实

- 247 条未决中，有 108 条来自多次实例化的 `Common_Tag_RedDot`。其内部有 Normal、Num、Unlock、Gift、Up、UpHigher、New 等控制器状态。它们不是 108 个不同的新设计决定，但也不能靠批量保留旧图或隐藏状态来消失。用户要求保留这些程序状态，**视觉资源不能沿用旧版**，并授权依据主页 PSD 风格推导缺失状态。
- PSD 是单张默认态设计，缺少这些状态的独立稿。推导出的状态需作为新设计资源落在原状态对象上，并逐状态显示验证；目前尚无该完整实现和验收。
- 共享组件定义的页面内写入还需要正式的按实例复制写入及候选校验。上面的变体只证明 Editor 可渲染，不证明全工程的资源依赖安全。
- 主页中多个 PSD 叶图层共同组成旧 FGUI 的一个视觉对象。现有一对一映射模型无法表达完整归属，仍有 54 条 PSD 侧未配对记录。不能把它们按区域打包隐藏，必须在候选中逐叶标明归属并生成原位资源。
- PSD 智能对象、图层效果、像素、形状样式、文字样式及画布外内容的无损验收仍有缺口。完整 F5 状态矩阵、转场、交互和游戏绑定均未通过。

因此当前不能宣称已达到全页最多 5 个逐对象判断，也不能批准候选。下一实现阶段须建立叶图层归属与按实例写入的正式契约，再生成推导状态资源并完成 Editor 全状态比对。
