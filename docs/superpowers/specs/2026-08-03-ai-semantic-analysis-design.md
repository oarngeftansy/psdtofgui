# AI 语义分析增强设计

## 目标

在现有 Figma 插件创建/更新 FairyGUI 工程的流程中加入在线 AI 语义分析，提高 Button、Label、List、Slider、组件状态、子节点角色和层级归属的识别质量，同时保留确定性转换、隐私控制和故障降级能力。

设计师仍然只使用 Figma 插件。AI 不直接生成或修改 FairyGUI 文件；现有 Python 转换核心仍是唯一产物生成者。

## 范围

本次包含：

- 支持 OpenAI API 和公司内网 OpenAI 兼容接口的服务端 AI 客户端。
- 结构化节点摘要的 AI 语义分析。
- 低置信度时由用户明确授权上传当前选择截图的二阶段分析。
- 严格 Schema 校验、几何安全校验、规则降级和诊断记录。
- 插件中的截图授权提示及降级状态展示。
- 自动化测试和管理员手动冒烟检查。

本次不包含：

- 在插件中存储或输入 AI 密钥。
- 默认上传截图或完整 Figma 文件。
- AI 直接写 XML、图片、ZIP 或本地 FairyGUI 工程。
- 自动训练、微调或长期保存设计数据。
- 复制第三方 `figma2fgui` 仓库的源码或文档。

## 总体架构

数据流如下：

```text
Figma 当前选择
  → 规范化节点树
  → 确定性规则预判
  → AI 结构分析
  → 置信度判断
  → 必要时请求截图授权
  → 可选的截图补充分析
  → 合并并验证语义决策
  → 现有转换与工程打包
  → 确定性检查
  → 下载 FairyGUI ZIP
```

新增的语义分析器位于服务端转换边界内。它只接收规范化后的最小输入，并返回受约束的语义决策。转换器不依赖某个具体模型供应商。

## AI 服务配置

管理员通过服务端配置提供：

- `provider`：`openai` 或 `openai_compatible`。
- `base_url`：官方 OpenAI 地址或公司内网兼容接口地址。
- `model`：部署批准的模型名。
- API 密钥：仅从服务端秘密配置读取。
- 请求超时、最大重试次数和并发限制。

两个供应商使用同一个兼容客户端接口。供应商差异不得进入分类、生成或插件代码。密钥不得写入日志、任务数据库、下载产物或返回给插件。

## 第一阶段：结构语义分析

默认 AI 请求仅包含当前选择的最小结构摘要：

- 节点 ID、名称、Figma 类型和父子关系。
- 相对尺寸、位置、旋转和源顺序。
- 组件识别所需的主要样式特征。
- 必要的文字内容；日志不得记录该内容。
- 确定性规则的候选类型、证据和置信度。

不包含其他页面、未选节点、完整 Figma 文件、访问令牌或本地工程内容。

AI 输出必须匹配版本化 Schema。每个决策最多包含：

- `node_id`
- `semantic_type`
- `fgui_name`
- `children_roles`
- `state_pages`
- `reparent` 建议
- `confidence`
- `risks`

允许的组件类型和角色名称由服务端规则定义。AI 不能增加不存在的节点，也不能提供文件路径、XML 或可执行内容。

## 第二阶段：截图补充分析

仅当结构分析低于配置的置信度阈值，或存在无法仅凭结构消除的视觉歧义时，服务端返回截图补充建议，包含面向设计师的原因和将上传的数据范围。

插件显示明确选择：

- 同意：只上传当前选择的渲染截图，再执行一次补充分析。
- 拒绝：不上传截图，立即使用已验证的 AI 结果和确定性规则继续生成。

拒绝截图不得阻止生成。授权只对当前任务有效，不得记为未来任务的默认同意。截图使用现有临时任务生命周期清理。

## 决策合并与安全校验

决策优先级为：

1. 通过 Schema 与安全校验的 AI 明确决策。
2. 项目配置中的确定性规则。
3. 现有默认规则。
4. 保守的通用 Component 降级。

每项最终决策保留来源、规则或模型标识、证据、置信度和风险，但不保存原始模型思维过程。

高风险建议必须额外校验：

- `node_id` 和角色引用必须存在于当前选择。
- `fgui_name` 必须满足现有安全命名规则并避免冲突。
- `reparent` 目标必须存在，不能形成环，且必须通过绝对边界包含关系检查。
- 状态页和子节点角色必须符合对应 FairyGUI 扩展组件约束。

无效的单项建议应被忽略并生成 WARNING，不应使整个任务失败。

## 故障与降级

以下情况自动降级到确定性规则并继续生成：

- AI 未配置或被管理员禁用。
- DNS、连接、超时、限流或服务端错误。
- 返回内容不是合法 JSON 或不符合 Schema。
- AI 引用了不存在的节点或给出不安全建议。
- 用户拒绝上传截图。

降级结果通过现有三级诊断展示为 WARNING；不得向设计师显示供应商响应、服务端地址、密钥、堆栈或完整提示词。只有现有转换或产物检查出现 ERROR 时才禁止下载。

## 插件体验

默认流程不增加配置项。设计师仍然选择当前画面、新建或更新方式及对应工程参数。

仅当需要截图时，插件插入一个非阻塞授权步骤。提示使用业务语言说明“仅靠图层结构无法可靠判断部分组件”，并说明只上传当前选择截图。用户同意或拒绝后都能继续。

结果页继续使用 INFO、WARNING、ERROR。可显示“AI 识别”“规则降级”“截图辅助识别”等安全摘要，不显示模型原始输出或内部置信度细节。

## 数据生命周期与日志

- AI 请求数据、可选截图和响应随现有临时任务一起清理。
- 默认不长期保存原始请求或模型响应。
- 日志只记录任务 ID、供应商类型、模型配置标识、耗时、状态码类别、Schema 版本和降级原因代码。
- 日志不得记录密钥、Authorization 头、完整提示词、节点文字、截图或完整模型响应。
- 内网兼容接口必须使用管理员批准的 HTTPS 地址；开发环境例外不得进入生产构建。

## 测试策略

### Schema 与安全测试

- 拒绝未知组件类型、未知字段、非法角色和虚构节点。
- 拒绝循环、越界或不存在目标的 `reparent`。
- 验证名称清理、重复名称处理和状态页约束。

### AI 客户端测试

- 覆盖 OpenAI 与内网 OpenAI 兼容配置。
- 覆盖成功、超时、限流、服务错误、无效 JSON 和 Schema 不匹配。
- 验证日志和异常中不存在密钥及敏感请求内容。

### 管线测试

- 验证合法 AI 决策优先于规则。
- 验证部分非法决策被忽略，其余合法决策仍可使用。
- 验证 AI 故障自动降级且产物仍可生成。
- 验证低置信度触发截图建议，拒绝截图后仍继续。
- 验证同一输入与同一已验证决策产生确定性产物。

### 插件与端到端测试

- 使用伪 AI 服务跑通纯结构分析。
- 跑通截图授权、上传和补充分析。
- 跑通拒绝截图和 AI 故障降级。
- 验证重复点击不会产生重复任务。
- 验证 ZIP 可解压、XML 合法、资源引用存在且原上传工程未修改。

默认自动测试不调用真实在线模型。管理员手动冒烟检查使用批准的非敏感测试文件，分别验证官方 OpenAI 和内网兼容接口。

## 验收标准

1. 普通设计师无需看到或配置 AI 密钥、模型地址或提示词。
2. 默认只发送当前选择的结构化最小数据。
3. 未经当前任务明确授权，不上传截图。
4. AI 完全不可用时，新建和更新流程仍可通过现有规则完成。
5. AI 输出不能绕过命名、层级、资源路径、ZIP 和 XML 安全边界。
6. 最终产物仍由现有 Python 转换器生成并通过确定性检查。
7. OpenAI 与公司内网兼容接口通过配置切换，无需修改转换逻辑。
8. 自动测试不产生真实模型费用，不发送真实设计数据。
