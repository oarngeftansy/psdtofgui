# 局域网集中式 Figma → FairyGUI 客户端同步方案

日期：2026-09-03  
状态：待用户最终确认

## 1. 目标

在固定 Windows 主机 `192.168.1.100` 上运行唯一一套 Writer 服务。设计师电脑不再安装 Git、Python、Node.js 或本地 Writer，只安装一次轻量同步器，并在 Figma Desktop 中导入一次固定路径的开发插件。此后服务端转换逻辑立即统一，插件文件由同步器自动更新，下一次打开插件时生效。

本方案解决以下实际问题：

- 每台电脑独立构建导致依赖、token、插件与 Writer 版本不一致。
- 用户误导入 `apps/figma-plugin/dist/manifest.json`。
- Writer 未启动、端口冲突或旧进程导致 `network`、`unauthorized`。
- Agent 只安装依赖却错误宣称系统可用。
- 更新失败后缺少可恢复的上一版本。

## 2. 明确边界

### 2.1 本期包含

- 一台局域网 Windows 服务端的安装、启动、升级、健康检查和回滚。
- 一个面向 Figma Desktop 的局域网插件发行包。
- 一个无需管理员权限的 Windows 客户端安装与同步器。
- 固定插件路径、自动版本检查、SHA-256 校验、暂存与回滚。
- 服务端与插件的兼容版本握手。
- 从真实 Figma 选择到可下载且可由 FairyGUI 6.1.4 打开的 ZIP 的端到端验收。

### 2.2 本期不包含

- Figma Community 或组织私有插件发布。
- 浏览器版 Figma。
- 正在运行的插件窗口热更新。
- 在客户端安装或运行 Writer。
- 通过脚本修改 Figma 私有数据库、自动点击导入对话框或绕过 Figma 安全限制。
- 跨公网、跨 VPN 或离线使用。

“同步”定义为：Writer 与转换规则在服务端部署完成后立即统一；Figma 插件在同步器完成更新并重新打开插件后统一。已打开的插件窗口不承诺热更新。

## 3. 总体架构

### 3.1 服务端

`192.168.1.100` 运行以下组件：

1. **Writer 服务**：处理选择上传、审核、项目构建和 ZIP 下载。
2. **局域网网关**：监听固定局域网端口，只允许公司网段访问，并转发到仅监听回环地址的 Writer。
3. **发行文件服务**：提供客户端安装器、插件发行文件、版本清单和校验值。
4. **服务监督**：通过 Windows 计划任务在开机时启动，在异常退出后重启并记录日志。
5. **持久数据目录**：位于 `C:\ProgramData\FigmaToFGUI`，升级不得删除。

Writer 继续仅监听 `127.0.0.1`。局域网网关负责外部监听、请求限制和服务端密钥注入。防火墙规则只允许批准的局域网网段访问，不把 Writer 暴露到公网。

本期固定局域网入口为 `http://192.168.1.100:8780`，Writer 内部入口为 `http://127.0.0.1:8765`。服务端新增显式 LAN 部署模式：只接受 RFC 1918 私有 IPv4 地址，不接受公网 IP、通配地址或任意 HTTP 域名。网关监听 `8780`，Windows 防火墙使用 `LocalSubnet` 约束来源。改变 IP 或端口视为一次需要重新发行插件的破坏性配置变更。

### 3.2 客户端

同步器安装到：

```text
%LOCALAPPDATA%\FigmaToFGUI
```

固定插件入口为：

```text
%LOCALAPPDATA%\FigmaToFGUI\plugin\manifest.json
```

客户端不保存源码仓库和构建依赖，只包含：

- 当前插件文件。
- 已验证的上一版本。
- 下载暂存目录。
- 非敏感版本状态与日志。
- “立即同步插件”和“打开插件目录”快捷方式。

首次安装完成后，安装器复制 manifest 路径到剪贴板并在资源管理器中选中该文件。用户只需在 Figma Desktop 中完成一次开发插件导入。

## 4. 发行与同步协议

服务端提供一个不可变版本目录和一个小型发行清单。发行清单至少包含：

以下是字段完整的示例；哈希和大小仅用于说明格式，发布时必须由构建器写入真实值：

```json
{
  "schemaVersion": 1,
  "releaseId": "2026.09.03.1",
  "pluginApiVersion": "1",
  "minimumServerApiVersion": "1",
  "files": [
    {"path": "manifest.json", "sha256": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa", "size": 512},
    {"path": "code.js", "sha256": "bbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbb", "size": 65536},
    {"path": "ui.html", "sha256": "cccccccccccccccccccccccccccccccccccccccccccccccccccccccccccccccc", "size": 262144}
  ]
}
```

同步器执行顺序：

1. 请求服务端 `/client/releases/current.json`。
2. 对比本地 `releaseId`。
3. 下载到新的暂存目录，限制文件名、数量和大小。
4. 校验每个文件的大小和 SHA-256。
5. 校验 manifest 的插件 ID、服务器地址和 `networkAccess`。
6. 若 Figma 正在运行，保留为待应用版本并提示重启 Figma；不得覆盖当前文件。
7. 若 Figma 未运行，将当前版本移动为上一版本，再将完整暂存目录切换为当前版本。
8. 启动后执行健康检查；失败时回滚上一版本。

服务端发布必须先写入不可变版本目录，完成全部校验后最后原子替换 `current.json`。客户端永远不下载“正在构建”的版本。

## 5. 认证与兼容性

- 插件访问 token 在服务端发行构建时注入插件，客户端 UI 不显示或要求用户输入。
- 网关密钥只存在服务端，绝不进入插件包。
- 服务端不因客户端来自局域网就移除插件认证。
- `/health` 只表示进程存活；新增安全的版本端点用于返回服务版本和插件协议版本。
- 插件发起业务请求时携带自身发行版本。
- 服务端发现插件协议不兼容时返回稳定错误码 `client_update_required`，UI 显示“关闭 Figma 后运行立即同步”，不得显示笼统的 `unauthorized`。
- 真正的凭证错误仍返回 `unauthorized`，但客户端日志只记录错误码，不记录 token。

插件 manifest 的 `networkAccess.allowedDomains` 仅包含 `http://192.168.1.100:8780`，并提供 Figma 对本地或开发服务器要求的 `reasoning`；不得使用 `*`、`localhost` 或其他地址。局域网地址、端口和插件 ID 在一次发行中保持固定。

## 6. 安装流程

### 6.1 服务端一次性安装

管理员在 `192.168.1.100` 上运行服务端安装脚本。脚本必须：

- 验证 Windows、Python、Node 和所需端口。
- 创建 ACL 受限的持久数据、密钥、日志和发行目录。
- 构建 Writer、Web UI 和 LAN 插件发行文件。
- 安装计划任务和最小范围防火墙规则。
- 启动服务并验证回环健康、局域网健康、版本端点和一次无敏感数据的测试生成。
- 生成客户端安装包与 SHA-256。

任何校验失败均返回非零退出码，不得打印“安装成功”。

### 6.2 客户端一次性安装

用户运行一个签名状态明确的 PowerShell 安装包。安装器必须：

- 验证服务端可达。
- 下载并校验当前插件发行版。
- 创建固定插件目录和用户级登录同步任务。
- 创建“立即同步插件”快捷方式。
- 复制并选中 manifest 路径。
- 明确提示唯一人工动作：在 Figma Desktop 导入该 manifest。

客户端安装不要求管理员权限。若企业策略禁止用户级计划任务，安装器退化为桌面“立即同步插件”快捷方式，并明确报告未启用自动同步。

## 7. 升级与回滚

服务端升级流程：

1. 在隔离目录构建并运行自动测试。
2. 用非敏感 Figma 固定样例完成端到端生成。
3. 保留当前应用、插件发行版和数据快照。
4. 停止服务，部署新版本，保留密钥与数据。
5. 健康检查通过后发布新的 `current.json`。
6. 失败则恢复上一应用版本和数据快照，不发布新插件版本。

客户端升级失败时保留当前插件；已经下载但未验证的文件不会进入插件目录。新插件与服务端不兼容时，服务端返回 `client_update_required`，客户端同步完成前禁止继续生成。

## 8. 错误与日志

服务端和客户端必须区分：

- 服务不可达。
- 客户端版本过旧。
- 插件凭证不匹配。
- 选择上传失败。
- 转换校验失败。
- XML 校验失败。
- ZIP 写入或归档校验失败。
- 输出发布失败。

UI 的“复制诊断信息”必须包含时间、发行版本、服务版本、稳定错误码和安全的失败阶段；不得只返回 `build_failed` 这种无法定位的外层兜底。日志不得包含 token、原始 Figma 文本、图片字节或完整选择内容。

## 9. 测试与验收

### 9.1 自动测试

- 发行清单模式和路径安全测试。
- 文件大小、哈希错误和截断下载测试。
- Figma 运行期间延迟应用测试。
- 原子切换和上一版本回滚测试。
- 插件/服务版本兼容矩阵测试。
- token 不一致、服务不可达和版本过旧的稳定错误码测试。
- 服务启动、异常退出和计划任务恢复测试。
- 防火墙与监听地址配置检查。

### 9.2 真实验收

在 `192.168.1.100` 和至少一台干净的同事 Windows 电脑上执行：

1. 客户端无 Git、Python、Node 环境也能安装。
2. Figma Desktop 首次导入固定 manifest 后可以打开插件。
3. 完成真实选择的读取、审核、确认和 ZIP 下载。
4. ZIP 通过 Writer 自校验，并可由 FairyGUI 6.1.4 打开。
5. 更新服务端转换规则后，同事无需操作即可使用新规则。
6. 发布新插件后，同步器下载；关闭并重新打开 Figma 后使用新插件版本。
7. 人为损坏下载和中断升级时仍保留上一可用版本。
8. 服务端重启后 token 不变化，既有客户端不出现 `unauthorized`。

只有以上八项全部有实际证据，才允许宣布可交付。单元测试通过、依赖安装成功或 `/health` 返回 `ok` 均不能单独代表产品可用。

## 10. 交付物

- 服务端 LAN 安装与升级脚本。
- Windows 服务/计划任务和防火墙配置。
- 当前插件发行目录及版本清单生成器。
- 客户端安装器、同步器和卸载器。
- 一页式首次导入说明。
- 自动测试、真实验收脚本和回滚操作手册。

## 11. 已知限制

- Figma Desktop 的首次开发插件导入必须由用户完成。
- 已打开的插件不会实时替换；更新在关闭 Figma 后应用。
- `192.168.1.100` 关机、离线或局域网不可达时所有客户端均无法生成。
- 没有 Figma 组织私有发布能力，因此无法获得 Figma 官方插件自动更新渠道。
- “100% 同步”只对已成功发布并通过客户端校验的发行版本成立，不包括未提交或尚未部署的本地修改。
