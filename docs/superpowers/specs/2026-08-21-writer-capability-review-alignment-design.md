# Writer 能力判定与审核流程对齐设计

日期：2026-08-21  
状态：已获需求方逐节确认

## 1. 背景

当前新建工程链路在真实复杂选择上存在两套不一致的能力规则：

- Figma 插件将渐变、阴影、复杂蒙版和组件实例等效果提前合成为 PNG；
- 后端 UIR/Plan 校验还会拒绝未被插件提前处置的视觉样式、局部变换和复杂富文本；
- 审核数据只在最终校验与候选打包成功后生成，因此最需要审核和调整的选择反而无法进入审核；
- 插件最终只显示笼统英文错误与“重试”，无法告知具体图层、原因和处理方法。

真实复现中，31 个资源全部上传成功，但选择在 Writer 前校验阶段因 25 个视觉样式、9 个不可表示变换和 9 个复杂文本 runs 被阻断。渐变、阴影等既有 PNG 保真处置本身正常，不是这次失败的直接原因。

## 2. 目标

建立一份由后端统一裁决的转换处置合同，使能力分析、审核、调整、生成和最终校验共享同一组确定性决策。

目标流程：

`选择上传 → 统一能力分析 → 生成三级审核 → 应用默认处置 → 构建候选 → 最终校验 → 批准下载`

成功标准：

1. 渐变、阴影、复杂蒙版等既有自动 PNG 保真能力不回归。
2. 后端不会再因插件未预见的视觉样式、变换或复杂富文本直接给出笼统失败。
3. 有安全自动策略的问题可以进入审核并生成候选；只有无安全策略的问题阻止批准。
4. 审核展示具体图层、影响、默认策略、允许调整和定位动作。
5. 同一输入产生稳定的处置顺序、审核内容和候选 ZIP 字节。

## 3. 非目标

- 不实现 Project Binding，不改变“更新现有工程”流程。
- 不加入村庄、页面名称、图层 ID 或业务组件特例。
- 不承诺将所有 Figma 效果转换为 FairyGUI 原生属性。
- 不放宽 Writer 的 XML、资源、目录、归档和发布安全门。
- 不以整体根节点无条件栅格化掩盖可编辑性问题。

## 4. 方案选择

### 4.1 采用方案

采用共享的后端权威“转换处置合同”。插件负责采集事实、按服务端要求导出资源和展示结果；后端负责决定原生、PNG 保真、可调整风险或阻断。

### 4.2 未采用方案

- **只扩展插件分类器**：改动小，但继续保留两套规则，无法防止后续漂移。
- **后端整体容器栅格化**：成功率高，但会过度丢失文本、层级和组件可编辑性。

## 5. 权威转换处置合同

每个需要裁决的源图层只产生一个权威 `conversionDisposition`：

| 状态 | 含义 | 默认行为 | 审核语义 |
| --- | --- | --- | --- |
| `native` | 可由当前 Writer 原生且确定性表达 | 原生生成 | 不显示或计入“原生”统计 |
| `raster_preserved` | 已通过整体 PNG 保留视觉 | 使用 PNG | 绿色“已自动保真”，不要求操作 |
| `editable_risk` | PNG 是安全默认值，但用户可能更在意可编辑性 | 默认 PNG，可选择服务端允许的可编辑策略 | 黄色“建议确认” |
| `blocked` | 没有可证明安全的自动策略 | 不生成可批准候选 | 红色“必须处理” |

每条处置至少包含：

- 稳定处置 ID；
- Figma 源图层 ID、显示名称和节点类型；
- 闭合的原因代码；
- 默认策略与后端声明的允许策略集合；
- 对视觉、可编辑性和组件复用的结构化影响；
- 定位图层引用；
- 是否阻断；
- 应用处置后的生成证据与鉴权预览引用（可用时）。

未知状态、原因或策略在严格客户端和服务端均失败关闭。处置顺序按稳定源身份和原因代码确定，不依赖异步完成顺序。

## 6. 职责边界

### 6.1 Figma 插件

插件负责：

- 采集 fills、strokes、effects、style references、blend mode、local transform、rotation、text runs、组件与蒙版事实；
- 上传闭合 selection manifest 与服务端要求的资源；
- 按服务端处置请求执行 PNG 导出；
- 严格解析并展示服务端审核；
- 执行定位、调整、重生、批准和下载。

插件不再独立决定某项能力是否最终受 Writer 支持，也不根据英文文案猜测调整策略。

### 6.2 后端

后端负责：

- 将 selection facts 统一映射为转换处置；
- 在最终 Writer 构建前生成可展示的三级审核；
- 应用默认处置或已批准调整；
- 编译 UIR/Plan、构建候选并执行既有五道门；
- 将最终校验结果映射回源图层和处置，而不是压缩成无上下文总错误；
- 保持 generation、旧候选失效、owner 鉴权和预览证据闭包。

## 7. 数据流与状态机

1. 插件提交不可变 selection manifest 和资源。
2. 后端执行能力分析，产出稳定 disposition 集合。
3. 对 `raster_preserved` 和 `editable_risk` 应用默认 PNG 策略；若还缺少对应资源，候选进入明确的资源导出阶段，而不是 Writer 校验失败。
4. 后端生成审核模型。`blocked` 项可以有审核模型，但候选不可批准。
5. 可安全生成时，后端编译并构建候选 ZIP，执行 Plan、payload、Manifest、XML/目录和 ZIP 重开校验。
6. 插件加载审核和预览；用户可以定位图层或修改黄色/红色项目允许的策略。
7. 调整产生新 generation，旧 generation 永久不可批准或下载。
8. 最终无阻断项、警告已确认且预览证据加载完成后，才允许统一批准并下载。

候选状态需要区分能力分析、等待资源、构建、待审核、调整、批准、拒绝和失败。可处理的 disposition 不是 terminal failure。

## 8. 默认策略

- 渐变、阴影、模糊、复杂蒙版和无法原生表达的视觉组合：默认 `raster_preserved`。
- 无法表示的旋转或局部变换：默认 PNG；若未来服务端能证明原生等价，可声明可编辑策略。
- 复杂富文本：默认 PNG，并标为 `editable_risk`，因为会失去后续改字能力。
- 组件实例：在没有完整自包含组件定义树时默认 PNG，并标明组件复用损失；不得根据名称猜组件定义。
- 资源缺失、交互语义无安全表达、组件定义与 PNG 均不可得等情况：`blocked`。

“兼容”应描述为具体结果：原生可编辑或 PNG 视觉保真。不得把已安全栅格化的项目笼统描述为“不支持”。

## 9. 审核交互

审核页按三级状态汇总：

- 绿色：已自动保真；
- 黄色：建议确认；
- 红色：必须处理。

每类默认折叠并显示数量，展开后显示具体图层、原因、影响、当前策略、允许调整和“定位图层”。重复警告不再在选择卡与页面中逐条堆叠。

绿色项目默认不要求操作。黄色项目默认采用 PNG，并由一次统一风险确认满足批准条件；用户可逐项切换服务端允许的可编辑策略。红色项目必须处理，没有安全策略时明确解释原因且不显示无意义的“重试”。

主流程文案使用中文并区分：

- 分析失败：重新读取选择；
- 资源导出失败：定位或重新导出资源；
- 存在红色项目：进入审核处理；
- 最终 Writer 校验失败：显示规则、图层和建议动作；
- 服务异常：重试请求。

## 10. 错误与隐私边界

- 公开诊断只包含闭合代码、公开中文文案、源图层安全身份和可执行动作。
- 不公开本地路径、token、资源字节、内部异常链或服务端存储路径。
- 预览继续通过插件鉴权客户端获取 Blob，不把受保护 URL 直接交给 `<img>`。
- 最终校验中出现未被 disposition 覆盖的能力错误时，候选失败关闭，同时返回可定位的公共规则；该情况视为能力合同漂移并由回归测试捕获。

## 11. 兼容与迁移

- 保持现有新建工程 REST 路径和候选身份模型。
- 在严格合同中加入 disposition/review 字段；旧候选无新字段时不被新客户端误判为可批准。
- 保持既有 ZIP、XML 和 Editor 6.1.4 方言不变。
- 保持原有渐变、阴影、蒙版和实例 PNG 导出路径，迁移为后端权威处置驱动。
- Web Console 的 legacy 默认路径和“更新现有工程”不受影响。

## 12. 测试策略

公共测试接缝为：

1. **Selection manifest**：视觉、变换和文本事实完整、严格、隐私安全。
2. **Writer REST 生命周期**：能力分析产生稳定三级处置；可处理项能进入审核；红项阻止批准但不吞掉审核。
3. **插件审核面板**：分类汇总、展开、定位、风险确认、调整与重生。
4. **Writer 产物**：默认处置生成的 Plan/Manifest/XML/ZIP 仍通过既有五道门。

垂直 TDD 回归至少覆盖：

- 渐变、阴影、复杂蒙版继续生成 PNG 且为绿色；
- 普通视觉样式不再因插件/后端规则漂移直接失败；
- 不可表示变换默认 PNG；
- 复杂文本 runs 默认 PNG 且为黄色；
- 黄色调整产生新 generation，旧候选失效；
- 红色项目有审核内容、可定位且不可批准；
- disposition 未覆盖的最终能力错误失败关闭并返回具体公共规则；
- 同一输入的 disposition、审核顺序和 ZIP 字节确定性一致；
- 真实复杂中立 fixture 覆盖多种视觉、变换与富文本组合；村庄选择只作为回归输入，不进入生产规则。

## 13. 验收标准

- 当前真实复杂选择不再得到单句 `The converted selection did not pass validation.`。
- 用户能在候选失败前看到三级审核汇总与具体图层。
- 默认 PNG 策略下，没有无安全语义的阻断项时可以生成并下载有效 FairyGUI 6.1.4 工程。
- 审核明确区分“原生可编辑”“PNG 视觉保真”“建议确认”和“必须处理”。
- 全量自动化、插件 production/dist parity、类型检查、静态检查和既有 Writer golden 均通过。
- GUI 验收只陈述实际可观察证据，不因本设计伪造截图或扩大 Editor 覆盖声明。
