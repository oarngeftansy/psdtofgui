# PSD 作为 HIFI 输入的接入方案

> 如果要求所有通过的交付都满足视觉无损和文字可编辑，应采用同目录下的《无损 HIFI 材料包输入合同》作为主方案。直接解析单个 PSD 只适用于能力兼容性检查，不能承担任意 PSD 的无损承诺。

## 目标

让 HIFI 替换流程先选择输入来源，并接受两种互斥来源：PSD 文件或当前 Figma 框选。PSD 是默认主入口，在插件内本地解析并写成一个新的 Figma 根 Frame；当前 Figma 框选是已有设计已经位于 Figma 时的快捷入口。两种来源随后复用同一套选择导出、对象映射、候选审核和 FairyGUI 交付流程。

## 关键决策

- 不尝试从本插件启动另一个 Figma 插件。Figma 一次只运行一个插件动作，也没有公开的跨插件调用 API。
- 采用开源 MIT 项目 `4NaNBo1/psd-to-figma` 的导入实现作为技术来源，固定审核过的提交，只抽取 PSD 解析、导入 IR 和 Figma 建层部分。
- 不接入它的 UI、PSD 导出、更新检查和网络权限；我们的 manifest 继续只允许本机 Writer。
- PSD 原文件只在插件 iframe 内解析。解析结果通过现有 main/UI 消息通道创建 Figma 节点，不上传 PSD 原文件。
- “无损保留”是交付门槛，不是转换器的默认能力。任何无法在 Figma 和 FairyGUI 中等价表达的 PSD 属性都必须阻断交付，不能静默丢弃、替换或栅格化。
- 文字必须保持为可编辑文字。三端使用同一套字体是必要条件，但仍需核对字体文件哈希、PostScript 名称、字重、字号、字距、行距、段落、基线和渲染结果；不能仅凭字体家族名称判定兼容。
- 原始 PSD 字节、SHA-256、图层 ID 和转换诊断随候选工程记录，保证每个输出节点可以追溯到原始图层。

## “无损”的验收定义

- **源文件无损**：原始 PSD 不被改写，保存文件哈希，转换过程可复现。
- **结构无损**：PSD 中每个有效图层、分组、顺序、可见性、混合、蒙版和效果都有明确且等价的目标表示；缺少等价表示时流程失败。
- **文字无损**：文字内容及可编辑性保留，字体文件与样式完全匹配；禁止把文字转成图片或轮廓来伪装通过。
- **视觉无损**：分别渲染 PSD 导入结果、Figma 根 Frame 和 FairyGUI 候选组件并执行图像差异检查。是否允许抗锯齿级微差必须作为验收参数明确配置；若要求逐像素相同，则任何非零差异都阻断交付。
- **行为无损**：旧 FGUI 根组件原有 Controller、Gear、Transition、引用和资源身份保持不变。

## 产品工作流

1. 导入旧 FairyGUI 工程，并确认要修改的指定目录与根组件。
2. 在“HIFI 来源”中二选一：默认选择 `PSD 文件`；也可切换到 `当前 Figma 框选`。
3. PSD 模式下拖入一个 PSD 和所需字体包，插件显示画布尺寸、图层数、字体文件校验、无法等价表达的属性和阻断项。
4. 用户点击“导入到当前 Figma 页面”。插件创建单个根 Frame，保留图层顺序，并为导入节点写入来源图层 ID 和类型元数据。
5. 插件自动选中导入根 Frame，进入“检查导入结果”。用户可返回 Figma 修正字体、命名或图层。
6. 当前 Figma 框选模式下，插件直接检查框选是否为单个合法根节点，并显示节点数、资源数和警告。
7. 两种模式都以“使用这个 HIFI”结束准备阶段，调用同一个 selection preflight/export；后面的目标目录、根组件、映射、候选、审核和交付不分叉。

```text
旧 FGUI 工程 → 指定目录与根组件
                         ↓
                  HIFI 来源（二选一）
            ┌────────────┴────────────┐
            │                         │
     PSD 文件（默认主入口）      当前 Figma 框选
            │                         │
     本地解析与质量检查           框选合法性检查
            │                         │
     创建并选中根 Frame           使用选中的根 Frame
            └────────────┬────────────┘
                         ↓
盘点与映射 → 局部修改 → 候选工程 → 对象/文件差异审核 → Editor 检查 → 交付
```

## 需要新增的模块

- `apps/figma-plugin/src/psd/parse.ts`：在 UI iframe 中读取 PSD ArrayBuffer，输出受限的导入 IR。
- `apps/figma-plugin/src/psd/contracts.ts`：PSD 文档、组、文字、位图、形状、蒙版和诊断合同。
- `apps/figma-plugin/src/psd/import.ts`：在插件主线程把 IR 写成 Figma 节点，处理字体加载和图片创建。
- `apps/web-console/src/figma/HifiSourcePicker.tsx`：PSD/Figma 来源二选一；PSD 作为默认入口，负责文件输入和解析进度；Figma 模式负责读取当前框选。
- `apps/web-console/src/figma/PsdImportReview.tsx`：导入前诊断和导入后的根 Frame 确认。
- `third_party/psd-to-figma/NOTICE.md`：记录上游仓库、MIT 许可、固定提交和实际复用文件。

## 导入边界

首版仅对能够证明等价的内容放行：组与图层顺序、可见性、不透明度、可编辑普通文字、普通位图、基础形状、基础混合模式和基础蒙版。

以下情况不得降级通过：

- 缺失字体或字体文件哈希不一致：阻断，安装并验证用户提供的字体包后重新检查。
- 智能对象：只有能保留其内容和变换语义时才放行；作为位图导入不算结构无损。
- 调整层与复杂效果：只有目标端存在等价表达并通过渲染差异检查时才放行；合成或栅格化不算无损。
- CMYK、专色、通道和超大 PSB：首版阻断并给出原因。
- 隐藏辅助层：保留层级、属性和来源身份，但默认不进入 HIFI 映射候选。

## 对现有映射的必要调整

- 默认只展示待确认项；自动匹配项收进“全部”筛选。
- 预览围绕当前对象局部放大，只绘制当前对象和最多 12 个邻近对象。
- PSD 导入节点优先使用 PSD 图层 ID、父路径和顺序作为匹配证据，不能只依赖名称和几何。
- 容器、蒙版基底、调整层和导入辅助节点不作为可新增 FGUI 视觉叶子。
- 数百图层时先按一级组分段，再进入对象级映射，避免一次出现 200 多项。

## 验收门

- 使用至少三份固定 PSD：纯位图 UI、含文字和分组、含蒙版/效果/智能对象。
- 首次进入 HIFI 来源步骤默认落在 PSD 文件；切换来源不会同时保留两个有效输入。
- 当前 Figma 框选和 PSD 导入产生的根 Frame 进入相同的 selection export 合同，后续页面不区分来源。
- 证明 PSD 在插件内解析且没有 PSD 文件网络请求。
- 验证字体包内实际字体文件的 SHA-256、PostScript 名称和样式映射；名称相同但文件不同必须判定失败。
- PSD、Figma 和 FairyGUI 三端对文字内容、换行、边界、字号、字距、行距、基线和样式逐项比较。
- 三端生成固定尺寸截图并执行差异检查；超过配置阈值时不得生成可交付 ZIP。
- 导入后的 Figma 根 Frame 与 selection export 合同一致。
- 同一 PSD 重复导入产生稳定的来源 ID 和图层顺序。
- 缺失字体、栅格化和不支持项在进入映射前可见。
- 使用 PSD 输入跑通现有 HIFI 候选与交付纵向测试。
- 在真实 Figma Desktop 和 FairyGUI 6.1.4 中完成一次人工验收。

## 实施顺序

1. 固定上游提交并完成许可、依赖和网络行为审查。
2. 建立 PSD IR、字体合同和三份固定样例，只实现解析与属性完整性测试。
3. 实现 Figma 建层、字体文件校验和导入质量检查。
4. 接入 HIFI 来源选择并自动选中导入根 Frame。
5. 给映射器加入 PSD 来源证据和辅助节点过滤。
6. 实现 PSD、Figma、FairyGUI 三端渲染差异门禁。
7. 跑通 PSD → Figma → HIFI 替换 → FairyGUI 的纵向验收；任何结构或视觉损失都必须得到阻断结果。
