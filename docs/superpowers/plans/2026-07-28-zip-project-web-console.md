# ZIP Project Web Console Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a UX designer upload a FairyGUI project ZIP, review understandable visual changes in a React three-column workspace, and approve a complete update that the Windows Agent safely applies to the matching local project.

**Architecture:** A standard-library ZIP boundary safely extracts uploads into content-addressed project versions; FastAPI stores project metadata and creates conversion jobs against those versions. A React/Vite Web Console consumes designer-facing APIs, while the existing Agent gains internal project fingerprint matching and keeps exclusive ownership of local writes.

**Tech Stack:** Python 3.11, FastAPI, Pydantic 2, SQLite, zipfile, Pillow, React 19, TypeScript 5, Vite 7, Vitest, Testing Library, Playwright

## Global Constraints

- The primary UI must not require users to understand snapshot, SHA-256, changeset, XML, resource ID, or file-operation terminology.
- ZIP defaults are 500 MB compressed, 2 GB uncompressed, 20,000 entries, 100 MB per file, and 20:1 aggregate compression ratio.
- Reject absolute, drive-qualified, traversal, NUL, duplicate-normalized, and symbolic-link ZIP entries before extraction.
- Accept a FairyGUI project at the archive root or under one harmless wrapping directory only.
- Approval applies to the complete update; per-file selection and delete operations remain unsupported.
- The Agent alone may write a local project, and it must refuse newer local work.
- Continue using fixture Figma JSON; do not add live Figma access, authentication, PostgreSQL, MinIO, or a .NET Agent.
- The desktop Web Console is fully interactive; mobile is view-only.
- Use TDD for Python and TypeScript behavior, and preserve every existing test.
