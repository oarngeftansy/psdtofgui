# 无损 HIFI 材料包输入合同

## 结论

如果业务要求不是“尽量转换”，而是“所有通过的交付都必须无损”，主链路应使用由 Photoshop 端导出的标准材料包。原始 PSD 解析可以保留为辅助检查，但不能作为唯一事实来源。

系统承诺的是：材料包要么通过完整性、结构、文字和视觉验证后进入现有 HIFI 替换流程，要么阻断并报告具体失败项。不能承诺任意 PSD 都能通过。

## 无损目标

- 非文字视觉元素保持最终渲染效果、透明度、尺寸、坐标和图层顺序。
- 文字保持内容和可编辑性，并保留字体、字重、字号、字距、行距、对齐、文本框、基线、颜色、描边和分段样式。
- 旧 FairyGUI 根组件的 Controller、Gear、Transition、资源身份和引用关系不变。
- 每个输出对象都能追溯到材料包节点和原始 PSD 图层。
- 候选工程渲染结果必须与材料包效果图通过规定的差异门禁。

“可编辑文字”和“逐像素完全相同”是两项独立要求。即使字体文件相同，Photoshop、Figma 和 FairyGUI 仍可能使用不同的排版和栅格化实现。如果要求文字区域也逐像素零差异，必须先用实际字体和目标运行环境做技术样片；验证不通过时不能通过栅格化文字来冒充可编辑文字。

## 材料包结构

```text
HifiMaterial.zip
├─ source/source.psd
├─ reference/composite.png
├─ reference/text/<text-node-id>.png
├─ layers/<render-unit-id>.png
├─ layout/nodes.json
├─ text/text.sqlite
├─ fonts/manifest.json
└─ manifest.json
```

### `manifest.json`

记录协议版本、画布尺寸、像素密度、颜色空间、导出器版本，以及包内每个文件的 SHA-256。插件首先校验路径、大小、哈希、重复 ID 和引用闭包；任一校验失败都拒绝导入。

### `layers/*.png`

- PNG 必须使用无损 RGBA、统一 sRGB 和源画布像素密度。
- 每张 PNG 表示一个能够独立合成的渲染单元，不以“PSD 中恰好有一个图层”为充分条件。
- 调整层、跨图层混合、组级效果和复杂蒙版必须在 Photoshop 导出端处理成能够按普通 alpha 顺序重建的渲染单元。
- PNG 使用紧边界导出时，JSON 同时记录逻辑边界和包含阴影、描边、模糊外扩的像素边界。
- 文字像素不得混入普通图层 PNG，避免与可编辑文字重复渲染。

### `layout/nodes.json`

每个节点至少包含：

- `id`、`sourceLayerId`、`parentId`、`name`、`kind`；
- `zIndex`、`visible`、`opacity`；
- `logicalBounds` 和 `pixelBounds`；
- 二维变换矩阵、旋转、轴心和裁剪关系；
- `renderUnitId` 或 `textRecordId`；
- 组件角色、可替换范围和是否参与 FGUI 映射；
- 内容哈希和父子顺序。

所有坐标使用同一个左上角原点和像素单位。禁止依赖文件名排序恢复图层顺序。

### `text/text.sqlite`

数据库只读打开，并校验固定 schema。至少包含：

- 文本节点：内容、文本框、换行模式、水平和垂直对齐、基线及变换；
- 文本分段：起止索引、字体 PostScript 名称、字重、字号、字距、行距、颜色、描边和 OpenType 特性；
- 字体引用：字体文件 SHA-256、PostScript 名称、family、style 和版本；
- 每个文本节点对应的参考文字 PNG 及其哈希。

如果现有 DB 结构已经确定，需要先提供 schema 和一份脱敏样例；插件不应猜测列含义。

### `fonts/manifest.json`

字体包由用户在运行流程前安装。清单保存期望的字体身份和哈希。本机服务检查 Windows 已安装字体，Figma 插件检查 family/style 是否可加载，FairyGUI 检查项目和目标运行环境的字体配置。三项都通过后文字才可进入转换。

## 工作流

```text
旧 FGUI 工程 → 指定目录与根组件
                         ↓
                  HIFI 来源（二选一）
            ┌────────────┴────────────┐
            │                         │
 标准 HIFI 材料包（默认）       当前 Figma 框选
            │                         │
 完整性/字体/结构/合成验证       框选合法性检查
            │                         │
 构建标准 HIFI 中间模型          导出标准 HIFI 中间模型
            └────────────┬────────────┘
                         ↓
盘点映射 → 局部修改 → 候选工程 → 三端差异审核 → Editor 检查 → 交付
```

Figma 在材料包链路中用于可视化检查和人工调整，但不再承担解释 PSD 全部语义的责任。Writer 直接消费经过验证的标准 HIFI 中间模型，避免重复从 Figma 反推已知坐标和图层数据。

## 必须执行的验证

1. 校验 ZIP 路径、文件哈希、PNG 尺寸、数据库 schema、节点引用和字体清单。
2. 按 JSON 顺序在本机重建非文字图层，与 `reference/composite.png` 的非文字区域做图像差异。
3. 在 Figma 创建文字并与对应的参考文字 PNG 比较文本框、换行和渲染差异。
4. 生成 FairyGUI 候选工程，在 FairyGUI 6.1.4 中渲染同尺寸截图。
5. 比较参考效果图、Figma 和 FairyGUI；结构差异为零，视觉差异超过门限时阻断。
6. 验证旧组件行为引用和资源身份没有变化后才开放交付按钮。

## 仍需固定的输入规则

- 文字 DB 的真实格式与 schema。
- PNG 是按 PSD 原始图层导出，还是由 Photoshop 导出器生成的独立渲染单元。
- 目标运行环境和实际文字渲染引擎。
- “视觉无损”对文字抗锯齿是否要求逐像素零差异。
- 设计中是否存在跨组件调整层、混合模式或智能对象。

这些规则没有固定前，不能对材料包做“无损兼容”的完成声明。
